gemergt. Jeder PR ist einzeln als Drei-Wege-Patch übernommen, ein Commit pro PR („Upstream #NNN: …“).

Bei den drei Datei-Aufteilungen (#210, #211, #212) ist die Upstream-Aufteilung übernommen. Danach sind die Fork-Änderungen
der alten Einzeldatei (Upstream-Stand `6cc3e91` bis Fork-`main`) Hunk für Hunk in die neuen Teildateien eingespielt.
Was nicht automatisch passte, ist von Hand an die Stelle gesetzt, an die Upstream den umgebenden Code verschoben hat.

## Prüfung

- **Build:** `dotnet build TiaMcpServer.slnx -m:1 /p:UseTiaPortalReferenceStubs=true` erfolgreich (Linux). Gebaut wurde nach jedem PR.
- **Tests** (`Category!=Packaging`, Linux):
  - Nach #212: 11.495 Tests, davon 478 fehlgeschlagen, **0 neue** gegenüber der Basisliste.
  - Nach #217: 11.530 Tests, davon 479 fehlgeschlagen. Der eine zusätzliche Fehlschlag ist der neue Upstream-Test
    `ProjectTreeBrowseRequestTests.CreateQueryHash_ExcludesPageSizeButBindsQueryFields` aus #217. Er ist plattformbedingt:
    Der Test fixiert den Hash eines Pfads, den `Path.GetFullPath` auf Windows als `C:\Projects\Sample.ap21` belässt.
    Unter Linux stellt die Funktion das Arbeitsverzeichnis voran, deshalb weicht der Hash ab.
    Der Hash-Code selbst ist unverändert; der Test muss auf Windows grün sein.
  - Alle übrigen Fehlschläge sind die bekannten plattformbedingten: `TiaMcpServer.FakeWorker.exe`, `powershell.exe`, Windows-Pfade.
  - Vor dem Merge ist ein voller Testlauf auf Windows nötig.
- Nichts davon ist live auf V21 getestet; die Übernahmen sind reine Umbauten und eine CLI-Fehlerbehebung.
