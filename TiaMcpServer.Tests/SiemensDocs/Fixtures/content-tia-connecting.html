Connecting to the TIA Portal

Introduction

TIA Portal Openness has the possibilities to

  • get running TIA Portal processes and attach to TIA Portal instances

  • start new TIA Portal instances, either with or without graphical user interface

Note

Since you always use TIA Portal Openness by loading Siemens.Engineering assemblies from a specific TIA Portal version, the returned processes are all from that same TIA Portal version. It is not supported to access different versions in the same AppDomain.

The app.config file and the AppDomain.CurrentDomain.AssemblyResolve event are two solutions for resolving the Siemens.Engineering assemblies during runtime.

Note

Resolving Siemens.Engineering assemblies is only needed for TIA Portal Openness applications, but not for TIA Portal Add-Ins.

Using the app.config file

Set “Copy Local: False” for every Siemens.Engineering assembly after adding the references to the project and clean the output directory.

By adding an application configuration file (app.config file) to a .NET project, you can customize how the Microsoft CLR locates and loads assemblies. The app.config file is deployed next to the executable and renamed to match the executable.

Note

The disadvantage of the app.config file is that it must contain the correct entries before the application starts. Changes cannot be made during program execution.

Example app.config file for .NET Framework 4.8:

<?xml version="1.0" encoding="utf-8" ?>
<configuration>
<startup>
<supportedRuntime version="v4.0" sku=".NETFramework,Version=v4.8" />
</startup>
<runtime>
<assemblyBinding xmlns="urn:schemas-microsoft-com:asm.v1">
<dependentAssembly>
<assemblyIdentity name="Siemens.Engineering.Base" culture="neutral" publicKeyToken="29bfe5fdf4ba5d3b " />
<!-- Edit the following version and path according to your required TIA Portal Openness version -->
<codeBase version="xx.xx.xx.xx"
href="FILE://C:\Program Files\Siemens\Automation\Portal Vxx\PublicAPI\Vxx\net48\Siemens.Engineering.Base.dll" />
</dependentAssembly>
<!-- Depending on your application, you may need to provide additional Siemens.Engineering assemblies -->
<dependentAssembly>
<assemblyIdentity name="Siemens.Engineering.Step7" culture="neutral" publicKeyToken="29bfe5fdf4ba5d3b" />
<!-- Edit the following version and path according to your required TIA Portal Openness version -->
<codeBase version="xx.xx.xx.xx"
href="FILE://C:\Program Files\Siemens\Automation\Portal Vxx\PublicAPI\Vxx\net48\Siemens.Engineering.Step7.dll" />
</dependentAssembly>
</assemblyBinding>
</runtime>
</configuration>

Using AppDomain.CurrentDomain.AssemblyResolve event

The assembly resolver must be registered at the earliest stage in the program.

Register the AssemblyResolve event before using any TIA Portal Openness types. This cannot happen in the same method. Place all TIA Portal Openness code in a separate method or separate class that is called only after event subscription.

Note: The .NET runtime will throw an exception if it encounters TIA Portal Openness types before the resolver is registered.

Important: This applies not only to method bodies but also to:

  • Class properties with TIA Portal Openness types

  • Method parameters with TIA Portal Openness types

  • Return values with TIA Portal Openness types

Even when placed in separate methods, these will be resolved during class loading.

When you move your TIA Portal Openness code outside the Program class, the resolver will be active before that classes are evaluated during runtime.

Example of recommended application code structure:

internal static class Program
{
static Program()
{
// First register assembly resolver at the earliest stage in static Program constructor
AppDomain.CurrentDomain.AssemblyResolve += OnAssemblyResolve;
}

public static void Main()
{
// Then call method with TIA Portal Openness code in separate class
HelloOpennessApp app = new HelloOpennessApp();
app.Run();
}

private static Assembly OnAssemblyResolve(object sender, ResolveEventArgs args)
{
// Code is shown in the next section
// ...
}
}

internal static class HelloOpennessApp
{
public void Run()
{
using (TiaPortal portal = new TiaPortal(TiaPortalMode.WithUserInterface))
{
// Do something with TIA Portal Openness
}
}
}

Example for a basic AssemblyResolve implementation where the installation path is given:

private const string OpennessFolder = @"C:\Program Files\Siemens\Automation\Portal Vxx\PublicAPI\Vxx\netxxx";

private static Assembly OnAssemblyResolve(object sender, ResolveEventArgs args)
{
AssemblyName requestedAssemblyName = new AssemblyName(args.Name);

string filePath = Path.Combine(OpennessFolder, string.Concat(requestedAssemblyName.Name, ".dll"));

// Only respond to requests for TIA Portal Openness; must ignore missing files
if (!requestedAssemblyName.Name.StartsWith("Siemens.Engineering.") || !File.Exists(filePath))
return null;

Assembly loadedAssembly = Assembly.LoadFrom(filePath);

// Check if details like version match the requested assembly
if (requestedAssemblyName.FullName != loadedAssembly.GetName().FullName)
throw new FileNotFoundException("TIA Portal Openness version does not match", filePath);

return loadedAssembly;
}

Note

These examples have demonstrated how to resolve multiple Siemens.Engineering assemblies using a robust and reliable approach. If your application architecture is very modular and your first class only accesses the TiaPortal class from Siemens.Engineering.Base.dll, it is sufficient to resolve only the Siemens.Engineering.Base.dll in your code. All subsequent Siemens.Engineering assemblies will then be automatically resolved by the Base library.

Note

Recommended way is using the TIA Portal Openness registry keys with the AppDomain.CurrentDomain.AssemblyResolve event.
